# v0.2.0-beta

Released 2026-10-29

Reworks how the access log is configured.

## Release notes

- **Breaking:** `MetricsRules` and `MetricsRule` are now `AccessLogRules` and `AccessLogRule`. A config using the old names fails to load until you rename them.
- **Access log on by default:** with no rule bound, every request is logged. Bind a rule with `Enabled: false` to turn it off for a route, a server or the whole gateway.
- **Filters:** a rule can limit what is logged with `Methods`, `ExcludePathPatterns`, `StatusCodes`, `MinStatus`, `MinLatencyMs` and `SampleRate`.
- **Precedence:** route, then server, then global. The most specific rule wins, even when it is disabled.
- **Rejected requests are logged:** requests refused before a route is resolved (400, 404, 502) now appear in the access log.
- **Config check:** `nocleye check` reports access log rules that do not exist and values that are out of range.
- **Caller id:** when a token has no id claim, the access log shows a short `cred:` fingerprint instead of the raw token.

Docs for these features: [observability](https://nocleye.com/docs/observability/).
