# v0.3.0-beta

Released 2026-11-01

Route by header, safer header rules, and a TLS rotation fix.

## Release notes

- **Breaking:** route keys were renamed. A config using the old keys fails to load until you rename them.
  - `PathPattern` -> `MatchOptions.PathPattern`
  - `RemovePathPatternFromFinalRoute` -> `BeforeForwarding.RemovePathPattern`
  - `AddPrefixToFinalRoute` -> `BeforeForwarding.AddPathPrefix`
- **Route by header:** a route can match by path, by header, or by both. Header matches are checked first, then the longest path.
- **Fixes:**
  - Fix TLS certificate rotation detection. A renewed certificate is picked up within 10 seconds, no restart needed. An invalid new certificate is ignored and the previous one keeps being served.
  - `HeaderRule.Set` now rejects `X-Nocleye-*` headers, so the real request and user identity can't be overwritten. It also rejects headers managed by HTTP or the proxy, and values with control characters. Identity headers such as `X-User-Id` and `X-Tenant` can still be set.
  - A route can no longer match on `Host` or on an invalid header name, which would silently never match.
- **Config check:** `nocleye check` reports every new rule with where it is and how to fix it. New warnings for a route that removes `Authorization` or `Cookie`, and for `AddHeader` setting the same header the route matched on.
- **Path prefix validation:** `AddPathPrefix` must start with `/` and not end with `/`.
- **Access log:** new `header_match` field showing which header matched the route.
- **Performance:** route lookup is about 90% faster.

Docs for these features: [servers and routes](https://nocleye.com/docs/servers-and-routes/), [header rules](https://nocleye.com/docs/header-rules/), [CLI](https://nocleye.com/docs/cli/), [observability](https://nocleye.com/docs/observability/).
