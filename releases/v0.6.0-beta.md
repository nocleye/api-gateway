# v0.6.0-beta

Released 2026-11-22

A rework of the metrics system, more detail in the access log about limits, auth and upstreams, and fixes for idle timeouts, request IDs and config reloads.

## Breaking and behavior changes

The metrics system was reworked to fix behavior that was never intended and to make the results more accurate and easier to use. Metrics are now chosen by group, families that gave misleading or redundant data were removed or replaced, and some series now report more reliable values. Check your dashboards and alerts against the changes below.

- **`--sPrometheusMetrics` now selects metric groups, not single families.** The groups are `requests`, `streams`, `auth`, `dependencies`, `access_log`, `gateway` and `usage_control`, and the presets are `core` and `all`. Every family in a selected group is always on. An unknown name is rejected, and the error lists the valid groups.
- **An empty `--sPrometheusMetrics` now means `core`.** Before, it meant no series.
- **Removed metric families:**
  - `gw_request_size_bytes` and `gw_response_size_bytes`. Use the new counters `gw_request_bytes_total` and `gw_response_bytes_total`, labelled `route` and `upstream`. A request or response with an unknown size is not counted.
  - `gw_upstream_last_success_timestamp_seconds`
  - `gw_sink_events_total` and `gw_sink_last_write_seconds`
- **`gw_unique_callers`**, Family is not available anymore, It will be reworked and released withing a new group in the future.

## New features

- **`gw_limit_rejections_total{rule,scope,kind}`** in the `usage_control` group counts requests refused by usage control. A rule removed by a config reload loses its series once the old config has drained.
- **New access log fields:** `limit_reason`, `limit_rule`, `limit_scope`, `dependency_state`, `auth_result`, `upstream_path` and `grpc_status_name` (`grpc_status` is kept). The stdout sink has the same fields.

Check all available options in the [documentation](https://nocleye.com/docs/).

## Fixes

- **Idle timeouts now wait the full configured time.** Active gRPC, WebSocket and HTTP connections could be closed too early. For example, a 5s idle timeout with activity every 4s closed the connection after about 12s.
- **The `X-Nocleye-Request-Id` response header and metric exemplars now always show the request's own ID.** Before, they could show a wrong or garbled ID.
- **Config reloads now retire the previous config cleanly.** Its shutdown steps run once, and its metrics no longer show up after the new config takes over.
